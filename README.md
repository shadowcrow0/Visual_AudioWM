# Visual_AudioWM

Audiovisual working-memory experiments in PsychoPy, with per-participant adaptive calibration of stimulus difficulty.
Two experiment lines live in this repository; they share stimuli and helper code but are separate experiments.

**Status date: 2026-10-27.** Code is complete for both lines; the blocker is human data.
Latest hand-off note for the next Claude Code session: `review/進度交接_2026-10-27.md`.

## 1. SFT / working-memory line (`SFT_WM_*`, `VAWM_*`) — being re-tested now

Task: remember two colours and two spoken consonants, then judge whether a probe (one colour + one sound) matches.
Each dimension has three probe levels — **T** (target), **H** (easy foil), **L** (hard foil) — and the H/L distances
are calibrated per participant with the original adaptiveSFT method (constant stimuli → lnrm2 fit → drift-separation
targets 2.0 / 0.5; see `DECISIONS.md`).

| File | Role |
|---|---|
| `SFT_WM_change.py` | One readable script: calibration (colour, then sound) → practice → 6 blocks × 24 study sets × 9 probes. During calibration every trial draws new targets (two colours, two sounds), each with its own H/L; the probe on the non-calibrated dimension is T, H or L. |
| `SFT_WM_nochange.py` | Identical except the non-calibrated dimension's targets are fixed for the whole calibration block (`OTHER_TARGETS_CHANGE = False`); its probe still varies over T/H/L. |
| `VAWM_simple.psyexp` | Builder version of the same experiment (routines/components kept so it can be opened in Builder); regenerated by `make_simple_psyexp.py`. |
| `VAWM_calibrate.py` → `make_adaptive_blocks.py` → `VAWM_nobox.py` | The original three-step pipeline (calibrate, write block csvs, run). Still works; the `SFT_WM_*` scripts are the simplified single-file form of it. |
| `adaptive_vawm.py` | Calibration logic (LNRM and Psi calibrators), colour helpers, block writer, and the analysis bridge to SIC/MIC. |

**Current status**
- Calibration, main task, data output and analysis bridge are implemented and exercised end to end with a simulated
  (LNRM race-model) participant: both dimensions calibrate to in-range H/L; the output feeds `adaptive_vawm.analyze_vawm`.
- Lab machine is set up: PyMC + nutpie installed into PsychoPy's own package directory (`setup_pymc_coder.bat`);
  a formal 1000/1000/4-chain fit takes about 70 s there. Scripts run directly from PsychoPy Coder.
- First human pilot (2026-10-19, `data/pilot_2026-10-19/`): 72 colour-calibration trials completed with correct reaction
  times (0.8–2.9 s), then stopped by the experimenter at the sound-calibration instructions. Two problems found and fixed
  that day: reaction times were measured from program start (keyboard clock never reset) and the H/L sounds never
  appeared during colour calibration (the change/nochange distinction had been implemented wrongly). Both fixed in
  `cd8c55a` and `728e648`.
- **Next:** a complete human run of `SFT_WM_change.py` and `SFT_WM_nochange.py` (participant id filled in), then
  `analyze_vawm` on the resulting `*_simple_main.csv`.

**Open decisions:** feedback is shown in practice only; participants judge only the dimension being calibrated;
provisional H/L used before a dimension is calibrated are ΔE 30 / 6 for colour and confusion counts 10 / 200 for sound.
All of these are constants at the top of the scripts.

## 2. GRT line (`GRTv3_ada.py`) — adaptive 2×2 design, awaiting a run

A 4-item audiovisual working-memory task with spatial cues (valid/invalid) built on a 2×2 General Recognition Theory
design: colour (CIELCh hue at fixed L\*/C\*, coordinate = ΔE00 arc length) × sound (a natural [bi] token in
speech-shaped noise, coordinate = SNR in dB). Both dimensions are calibrated per participant with Adaptive-GRT's
`AGRTHandler` (two independent Psi staircases) before the main task. `GRTv3.py` is the fixed-level version,
`archive/GRTv3_a.py` the predecessor. Details and limits: `CLAUDE.md`.

## Running (lab machine, PsychoPy Coder)

1. Once per machine: run `setup_pymc_coder.bat` (installs pymc, numba, arviz, nutpie and the adaptiveSFT fork into
   `%APPDATA%\psychopy3\packages`, which is the only user-site Coder sees).
2. `debug_adaptivesft.py` — one-click diagnostic of the whole calibration chain (environment, fork lookup, imports,
   headless simulated calibration, a short real fit, and a dry run of `VAWM_calibrate.py` up to the dialog).
3. Open `SFT_WM_change.py` or `SFT_WM_nochange.py` in Coder and Run. `--robot --quick` on the command line runs the
   whole flow in a few minutes with a simulated participant and no window.
4. Wear headphones. On a machine you have not used before (e.g. a remote PC), find the output device first:

   ```
   python audio_pick.py                     # table of every output device; marks names that look like headphones
   python audio_pick.py --probe --beep      # also open each device, then play a 1 s tone on the chosen one
   python audio_pick.py --set "Headphones"  # remember that device (audio_device.txt + PsychoPy preference)
   ```

   Every experiment script then takes the device from, in this order: `--audio-device "NAME"` on the command line,
   the environment variable `VAWM_AUDIO_DEVICE`, `audio_device.txt`, or an automatic choice (headphone-like name >
   saved PsychoPy preference > anything that opens). A named device must exist or the script stops and lists what is
   there; `--require-headphones` makes the automatic choice stop instead of falling back to speakers
   (`GRTv3_ada.py` always requires headphones). The chosen name is written into every data row (`audio_device`).
   `--list-audio` on any script only prints the table. Logic and tests: `audio_pick.py`, `tests/test_audio_pick.py`.

Outputs per participant (in `data/`): `<id>_simple_calib_trials.csv`, `<id>_simple_calib.json` (H/L),
`<id>_simple_main.csv` (one row per probe; read by the analysis), plus PsychoPy's standard
`<id>_SFT_WM_<date>.csv / .psydat / .log`.

## Repository map

- `review/` — dated decision records (why each design choice was made, including abandoned paths); `90_Sources/` —
  literature cards; `DECISIONS.md`, `adaptive_vawm.md` — calibration decisions and install notes; `figures/`,
  `review/fig/` — procedure figures (note: `figures/` describes the VAWM_nobox line, `review/fig/` the GRTv3_ada line).
- `stimuli/` — 12 talkers × 16 consonants (`T??_<cons>3.wav`), the Kutlu & McMurray beach–peach continuum and its
  CV-trimmed tokens, response-box images. `rule.csv` at the root is the one `VAWM_nobox.py` reads.
- `archive/` — scripts and outputs that the decision records cite but nothing runs any more (see its README).
- `Adaptive-GRT/` — submodule, the Adaptive-GRT fork used as reference. The adaptiveSFT Python port lives in its own
  repository (`shadowcrow0/adaptiveSFT`) and is found at runtime via `ADAPTIVESFT_PATH`, a sibling checkout, the
  pip-installed editable copy, or `adaptivesft_path.txt`.
