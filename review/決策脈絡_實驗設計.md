# 決策脈絡 — GRTv2.psyexp 的隨機化與試次計畫

## 結論

`GRTv2.psyexp`(commit `39fd25e`)。study/task 的位置-內容-時間三重綁定拆開,
slot 改名 UR/UL/BL/BR,試次計畫改成完全交叉的平衡序列。

**試次計畫**(`study` → `pattern` → Begin Experiment):

```
valid   : target_item(4) × serial_pos(4)                = 16 格 × 24 = 384
invalid : target_item(4) × relation(3) × serial_pos(4)  = 48 格 ×  4 = 192
總計 576,分 12 個 block × 48
```

實測(576 試次 e2e 模擬,直接執行從 psyexp 抽出的 code):

```
每 block 恰好 48 試次,valid 比例 0.667,serial_pos 12/12/12/12
valid   每個 (item × serial)         = 24  (全等)
invalid 每個 (item × rel × serial)   =  4  (全等)
valid 試次的 intrusion 恆為 0
valid: cue_idx == target_quad ;invalid: cue_idx != target_quad
```

**relation 的定義**(XOR 編碼,`colour = i&1`, `sound = (i>>1)&1`):
`target ^ 1` = 只差顏色,`^ 2` = 只差聲音,`^ 3` = 兩者都差。
**平衡 relation 是後續能把 intrusion 從知覺混淆裡分離出來的前提** —
見 [[決策脈絡_統計方法]]。

## 被推翻的假設

### ❌「`rng.permutation(4)` 每次不同,所以刺激有隨機化」

**排列每次確實不同,但完全沒有效果。** 原本的 code:

```python
order = rng.permutation(4)
posAx, posAy = POS[order[0]]        # 位置
TimeStartA   = START[order[0]]      # 時間
StudyA       = itemColhex[order[0]] # 內容
```

三者用**同一個索引**。令 `j = order[k]`,slot k 就是「在象限 j、於 START[j]、
呈現 item j」。四個 slot 跑完,顯示的集合永遠是
`{(象限 j, 時間 START[j], item j) : j=0..3}` —— **與排列無關**。

實測:**200 個試次只產生 1 種畫面**。受試者跑幾十試次就能學會
「右上角一定是 C1+b3、而且最先出現」。

`task` routine 有**完全一樣**的問題(`txtUL_pos = POS_TXT[orders[0]]` 與
`UL_col = final_value[orders[0]]`),所以四個反應選項也從來沒有移動過。

**修正**:兩個獨立排列(`content_perm`、`time_perm`),位置固定。
修正後 200 試次產生 173 種不同畫面,item 在各象限的分布均勻(50/59/52/39,期望 50)。

### ❌ 我一開始把 v1 的「位置用 cue、顏色用 target」讀成 bug

**那是刻意的設計。** invalid trial 上:

```
study:   位置A 放 item X      位置B 放 item Y
cue:     指向位置A                          ← 注意力被拉到 A
probe:   畫在位置A,但內容是 item Y          ← 衝突
task:    受試者報告 X 還是 Y?
```

報 Y = 刺激驅動勝出;報 X = **注意力捕獲**(intrusion)。
而且因為四個 item 是完整的 2×2,X 與 Y 的關係可以是「只差顏色」「只差聲音」
「兩者都差」,所以能知道注意力轉移影響的是哪個向度。

⚠️ **但 `GRTv2.py`(舊的匯出檔)把 `cue_color` 從 `itemColhex[target_quad]`
改成 `itemColhex[cue_idx]`,這會消滅衝突** —— X 和 Y 變同一個,intrusion 無從發生。
若那份是主線,這一行要改回 `target_quad`。

## 一併修掉的既有 bug

| 位置 | 問題 |
|---|---|
| `study` End Routine | `thisExp.addData('Ans', NAMES[k])` 的 `k` 是上面 for 迴圈的殘留值,永遠是 3 → `Ans` 恆為 `'BR'` |
| `task` End Routine | `correct_quad_name` 只在 if 分支賦值卻在外面讀 → 第一次沒按鍵就 NameError |
| `task` 元件 `vUR` | colorSpace 是 `rgb`,其他三個色塊是 `hex`,餵 hex 字串會出錯 |

## 技術細節:psyexp 的換行編碼

PsychoPy 把程式碼裡的換行存成**字面上的 `&#10;` 五個字元**
(檔案裡是 `&amp;#10;`)。直接寫真正的換行會被 XML 屬性正規化吃掉,
PsychoPy 讀進去會變成單行。

第一次產生 GRTv2.psyexp 時我踩到這個(174 個裸換行),已修正。
驗證方式:`grep -c '&amp;#10;'` 應為全部,`grep -c '(?<!amp;)&#10;'` 應為 0。
