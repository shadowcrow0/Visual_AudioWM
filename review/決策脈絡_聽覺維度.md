**傾向 SNR 的關鍵依據**是 [[silbert2012]] —— 最接近的已發表 2×2 GRT 語音前例,
用自然 token + speech-shaped noise(−3 dB SNR),理由是**方法論上的**:

> "In order to avoid strong assumptions about the relevant acoustic-phonetic dimensions,
> naturally produced nonsense syllables were used as stimuli."

> "Naturally produced [i.e., not (re)synthesized] tokens can be very acoustically
> distinct, however, and identification data with very high accuracy is not particularly
> informative with respect to perceptual interactions."

(四段方法段引句我已從 PMC 全文逐字核對。)

GRT 要估的是知覺分布的形狀與相關;若刺激只沿單一實驗者選定的參數變動,
估到的維度就被那個選擇預先決定。**「固定 F1、只動 VOT」正是那種單一參數設計。**
⚠️ 這個論證的強度、以及 GRT 文獻裡是否為共識,正在查證中(見 [[natural-vs-synthetic-speech]])。

## 反轉紀錄

### ❌ 1.「`duration_diff` 在操弄難度」

`generate_b3_p3_auditory_baseline.py` 的縮放邏輯把兩個時長**同乘** `1/scale`,
差距因此跟著同比例縮放且方向相反。實測:

```
要求 diff  |  舊版實際 diff  |  舊版子音長度
   5 ms    |     180 ms      |  b=540, p=720   ← 要 5 得到 180
  30 ms    |      30 ms ✓    |  b=90,  p=120
```

**目前產生的 40 組 baseline 刺激難度是反向排列的。** 已修正(commit `1ee76c4`)。

### ❌ 2.「修好縮放就等於在操弄 VOT」

**沒有。** 修正後用真實參數合成並量測:

```
 diff | b_dur p_dur |  VOT(b)  VOT(p) |  ΔVOT
    5 | 102.5 107.5 |      11      92 |     81
   30 |  90.0 120.0 |      10      98 |     88
   50 |  80.0 130.0 |      11     109 |     98
```

`duration_diff` 從 5 掃到 50 ms,**ΔVOT 只從 81 動到 98**,而 `VOT(b)` 幾乎釘死在
10–11 ms。b 與 p 之間永遠隔著約 80–98 ms 的 VOT 鴻溝,遠超辨識閾。
**修的是算術,底層操弄從一開始就沒碰到 VOT。**

### ❌ 3. 我說「b/p 是類別知覺,不能當 AGRT 維度」

**講太滿。** VOT 本身就是連續的物理維度,而且沿 VOT 的**辨識**函數是 probit 可擬合的
sigmoid —— 正是 AGRT 假設的形狀。用 A1–A5 檢查:

| | 刺激沿維度移動 | 二元反應與維度位置單調相關 | 有習得的界線 α |
|---|---|---|---|
| VOT / F1 起始 | ✅ | ✅ 報 b/p ↔ 維度位置 | ✅ 類別邊界 |
| SNR | ❌ 端點固定 | ❌ b/p 與 SNR 無關 | ❌ |

**VOT 比 SNR 更符合 AGRT 結構。** 阻礙從來不是模型,是合成器。

### ❌ 4.「MBROLA 的 `.pho` 可以精確設 ms」

**只在規格層成立。** 實測母音時長(子音固定 60 ms,F0=180 Hz):

```
1 ms 步進掃描 370→385 ms:
  實際母音長 [365.8, 365.6, 371.2, 371.2, 371.2, 371.2, 371.2, 376.8, ...]
  16 個請求值 → 只做出 6 個相異音檔,階梯 ≈ 5.5 ms = 1/180 Hz
```

**量化到音高週期。** 子音 VOT 同樣如此,而且**非單調**(請求 +1 ms 常讓實測 VOT 下降)。
非單調對 Psi 是致命的。

而且 `AGRTHandler.addResponse(intensity=...)` 會丟
`RuntimeWarning("Specifying an alternative intensity is not currently supported")`,
所以不能用「回報實際呈現值」繞過。緩解只能是把網格調粗:
F0=180Hz 時 `dim2steps ≤ 47`,250Hz 時 ≤ 65。

### ❌ 5. 我說「cross-splicing 只能產生固定網格」

**錯。** Winn (2020) §V.A 明確說明 crossfade 的用意就是解除這個限制:

> "First, it frees the process from the need to concatenate only at zero crossings,
> **which would place limitations on the minimal change in VOT that could be included in
> a continuum**."

送氣擷取長度補償一半的混合時間,"so that the output VOT should be exactly as the user
intends"。**是 sample-accurate 的任意實數。**

### ❌ 6. 兩份研究對 KlattGrid 時間解析度結論相反

一份說量化到音高週期(80 Hz 時誤差 4.04 ms),另一份說取樣點解析度(0.023 ms)。

**我自己測了,答案是取樣點解析度,而且兩份都沒測錯 —— 它們測的是不同東西。**

關鍵是我加了一個對照:**送氣噪音是未設種子的隨機源**。

```
同樣參數呼叫兩次:
  純嗓音(無送氣) : 最大差異 0.00e+00  → 可重現
  含送氣+burst   : 最大差異 8.08e-01  → 不可重現
```

所以「波形不同 = VOT 有動」不成立。必須在純嗓音條件下量:

```
  請求VOT    實際onset      Δreq      Δgot
   20.000     20.0227
   20.023     20.0454      0.023    +0.0227   ← 0.0227 ms = 44.1kHz 的一個取樣點
```

決定性驗證 —— 若是脈衝量化,階梯應隨 F0 縮小:

```
  F0=100Hz (週期 10.00 ms) → 階梯 0.227 ms
  F0=300Hz (週期  3.33 ms) → 階梯 0.227 ms   ← 完全不變
```

**用週期性偵測器(自相關)量必然量化到音高週期**,因為要累積至少一個週期才能判定。
**我自己前一次量到 8.481 ms 階梯也是這個原因,那個中間結果不作數。**

⚠️ **實務含意:如果你用 Praat 的 pitch tracker 驗證刺激,會誤判成量化的。**
驗證方法本身會製造假象。

## SNR 路線的性質

**dB 本身已經是對數尺度**,所以不需要像音長(取 log)或色相角(換 ΔE00 弧長)
那樣先做座標變換,A1/A2 直接滿足。

但 **SNR 是難度旋鈕,不是 GRT 意義下的維度** —— 受試者報告 be/pe(類別),
不是「吵還是乾淨」;端點固定;改變的是有效 β 不是 x。
所以聽覺要用一維 `QuestHandler`(找**一個** SNR),不能用 `AGRTHandler`
(它回傳對稱的**兩個**值)。詳見 `snr_vs_grt_dimension.md`。

`snr_audio.py` 實測:SNR 精度 3.9e-15 dB、可分辨 0.001 dB、running noise 正常、
削波已消除、噪音頻譜與語音 LTAS 各頻帶差 0.1–0.6 dB。
