# 決策脈絡 — 顏色維度

## 結論

固定 **L\*=55、C\*=38**,只動色相角,距離用 **CIEDE2000** 量,錨點 **303°**。
AGRT 的座標是**帶號 ΔE00 弧長**,不是度數。實作在 `agrt_setup.py`。

實測(`python3 agrt_setup.py`):

```
單調性         通過(最小步長 2.159e-03 dE00)
色域           ±60° 在 C*=38 下只有 93.9% 在 sRGB 內,偏藍側 h≈250.3 出界
               可用對稱半長 = 24.1372 dE00  ← 用 arc_range_in_gamut() 夾值
色相非均勻性   54.1%(每度 dE00 從 0.3598 到 0.5546)
8-bit 解析度   可用弧段上只有 300 種相異色,中位間距 0.148 dE00
beta 上限      10.45 dE00(半範圍 24.14 / 2.3107)
與 CSV 對照    set 17/18 hex 完全相同,set 19 差一階
```

**為什麼要用 ΔE00 弧長而非度數**:54.1% 的非均勻性就是直接餵度數會違反
A2(等變異)的幅度 —— 同樣一度的色相角,在弧的一端所值的知覺距離是另一端的 1.54 倍。

## 被推翻的假設

### ❌「現有的 #B744A1 / #B52C95 是色相操弄」

**不是。** 實測:

```
#B744A1   L*=48.0  C*=63.3  h=334.4°
#B52C95   L*=43.9  C*=68.9  h=337.4°
dE00 = 4.38   拆解: dL*=-4.0  da*=+6.6  db*=+0.9
```

**色相只差 3.0°,差異幾乎全在明度(-4.0)和彩度(+5.6)上。**
所以那個「顏色維度」實際上是明度+彩度的混合,不是色環距離。
對 GRT 而言,可分離性檢定的「維度」定義不清。

### ❌ 我提議的錨點 h=230°(藍區)

我量到 h=230° 附近 ±30° 的 dE00/度變異只有 17%,是所有候選裡最均勻的,
因此提議用它。**但這忽略了研究問題本身。**

使用者的 `colorWM.md` Q2 已經定案,理由是**範疇知覺**:

- **283° 是藍/紫類別邊界,不能用** — 跨類別配對會讓受試者拿到現成的顏色名字去區分,
  跟「口語分不出來但知覺可辨」的前提直接矛盾
- **293° 也不夠好** — 藍色分量仍偏高,離邊界只有 10°,個體間邊界位置有落差
- **選 303°** — 明顯偏紫/薰衣草,同類別標籤一致性高,離邊界 20° 有安全邊際

**我一度把 283° 當預設值交給 subagent —— 正好是筆記裡明說要避開的那個。**
教訓:先讀完專案既有筆記再提議。

### ❌ 子代理算的「可支撐最大知覺 SD 約 20.99 dE00」

它把 `AGRT.py` 的 beta 上限公式分子當成**全範圍**,實際是**半範圍**
(`np.average(dim1range) - dim1range[0]` = 中點到邊緣的距離)。

正確值是 **10.45 dE00**(24.1372 / 2.3107)。差一倍。

結論不變(文獻上 WM 延宕比較的顏色 SD 約 3–8 dE00,餘裕仍充足),
但這個數字會被拿去定 `dim1range`,不能錯。已修正並加 `max_supportable_sd()`。

### ⚠️ 色域不是全範圍可用(非推翻,是新發現的限制)

`SPAN_DEG=60` 在 C\*=38 下**不是**全部在 sRGB 內。偏藍側 h≈250.3 出界
(該處最大可用 C\* 只有 35.47)。**必須用 `arc_range_in_gamut()` 而非
`arc_range()` 去夾 AGRT 的提議值。**
