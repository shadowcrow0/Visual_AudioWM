## 0. 一句話

**我們一直在找「一個連續、單調、可控的子音維度」,四條路都走過了,
沒有一條同時滿足「可控」與「還是語音」。** 技術上做得出來的那條(SNR)

## 2. 逐項說明

### 2.1 子音時長 —— 修好了才發現問題不在 bug

原始腳本 `generate_b3_p3_auditory_baseline.py` 的 `_durations_for_diff` **縮放方向寫反**:
要求「差異加大」時實際做出來的差異變小。已修正(commit `1ee76c4`),改成
以 `CONS_MID_DUR` = 105 ms 為中心**對稱配置**,並補上 `TOTAL_MS` = 1000 的尾端補零
與 `floor(x+0.5)` 量化。

**但修好之後真正的問題才浮現:時長不是 /b/–/p/ 的主要區辨線索,VOT 才是。**
沿時長軸移動,受試者聽到的不是「更像 p」,而是「同一個音,長一點」。
這條軸單調、連續、可控,**只是它量的不是我們要的東西**。

⚠️ **而且經實測,這個參數從頭到尾沒有碰到 VOT** ——
把 `duration_diff` 從 5 掃到 50 ms,實際 ΔVOT 只從 81 走到 98,
變化來自別的地方。**這個操弄與它宣稱的目標無關。**

### 2.2 VOT via MBROLA —— 工具層級的死路

VOT 是正確的維度:連續、單調、是 voicing 的主要線索,
而且比 SNR **更**符合 AGRT 對維度的要求。

**但 MBROLA / espeak 渲染不出它。** 實測結果:

- /b/ 的 VOT 被**釘死在 −6.5 至 −2.5 ms** 的窄區間,無論參數怎麼給
- **非單調** —— 參數增加不保證 VOT 增加
- 這不是設定問題,是**規則式雙音素串接合成的架構限制**:
  MBROLA 從錄好的 diphone 資料庫串接,VOT 已經烘焙在資料庫裡,不是可調參數

⚠️ 順帶更正一個我自己的測量錯誤:我一度量到 KlattGrid 的 VOT 步階是 8.481 ms,
**那是錯的** —— 我用了自相關偵測器,而週期性偵測器**按建構方式**就會把時間量化到基頻週期。
改用純發聲判準的乾淨測法後,實際解析度是 **0.0227 ms(取樣點層級),且與 F0 無關**。
**所以 KlattGrid 沒有解析度問題,問題在別處(見 §2.5)。**

### 2.3 ⛔ `be.wav` / `pe.wav` 從來不是自然錄音

**這是整條線最關鍵的事實認定錯誤,也是最該讓老闆知道的一條。**

專案文件通篇把聽覺刺激描述成「自然 token + 噪音」。實測:

```
be.wav  vs  espeak-ng "[[b'i:]]"  →  max |diff| = 0.0   (逐取樣點完全相同)
```

`stimuli/` 底下的 **209 個檔案全部是 MBROLA 合成**。

後果是**兩邊的好處都沒拿到**:
- 沒有自然音的**生態效度**(它是規則式共振峰合成)
- 也沒有合成音的**參數可控性**(我們沒有在控制任何語音參數,只是拿它當固定素材)

### 2.4 自然錄音 —— 查遍了,拿不到

要的條件是:**孤立的 CV 音節、自然、/b/–/p/、母音最好是 /i/**
(Winn 2020 明確指出 /i/ 脈絡下 F1 不會隨 VOT 共變,是最乾淨的選擇;
/ɑ/ 則是「特別不幸的選擇」)。

| 來源 | 結果 |
|------|------|
| **Goldenberg et al. (2022)** 的 24 檔 | ⛔ **Dropbox 檔案已刪除**。這是唯一同時滿足「孤立 + 自然 + /b/–/p/」的來源。連結仍回 HTTP 200 但內容 `<title>` 是 "Dropbox - File Deleted";PMC 與 Frontiers 都沒備份。只能寫信給作者。(母音是 /ɑ/,本來就非首選) |
| **LDC2015S12** | ✅ 存在,$0,有 `f101_s_bi.wav` / `f101_s_pi.wav`,但 **16 kHz** |
| **OSF Kapnoula** VOT×F0 | ⚠️ 孤立 CV 且有二維格點,但母音 /ʌ/ |
| **OSF Kutlu & McMurray** | ⚠️ 母音 /i/ 正確,但是 **CVC 單詞**不是孤立音節 |
| Buckeye / CMU-ARCTIC / Common Voice 等大語料庫 | ⛔ 連續語流,不是孤立音節 |

**cross-splicing 本身沒問題** —— Winn (2020) 明講 crossfade 是取樣點精確的,
Goldenberg 也正是這樣做的。**卡住的是沒有可以拿來 splice 的錄音。**

### 2.5 KlattGrid —— 唯一技術上通的路,但代價要講清楚

解析度沒問題(0.0227 ms)。真正的代價是:

1. **要從零建立參數集** —— F0 軌跡、共振峰軌跡與頻寬、送氣噪音、burst 頻譜,
   每一項都要調到聽起來像 /bi/ 與 /pi/,而且要通過辨識前測。這不是一兩天的工作。
2. **回到純合成**,而且是比 MBROLA 更「無語者」的合成。
3. ⚠️ **Brunswik (1955) 的批判正對著這個做法** ——
   把 F0、F1 釘死、只動 VOT,正是他點名的「人為誘發的完美混淆」。
   合成不是解方,是**把混淆從隨機換成固定**。
4. ⚠️ **Clark (1973) 的判準**:單一合成刺激只能撐**點假設**
   (「在 VOT = X、F1/F0 = Y 的這個刺激上」),撐不起「voicing 表徵與顏色有關」
   這種**類別層次的集中趨勢假設**。

### 2.6 SNR —— 做成了,而且做得很乾淨,但它偏題

`snr_audio.py` 已完成並通過驗證:

| 驗證項 | 結果 |
|--------|------|
| SNR 誤差 | **3.55e-15 dB** |
| 解析度 | 0.001 dB 可分辨 |
| 各 token 聲學起點對齊 | **0.00 ms**(原本差 35.9 ms) |
| 發聲段位準差 | **0.000 dB**(原本差 1.62 dB) |
| 削波 | 無(峰值 ~0.21) |
| running noise | 已確認每 trial 換新樣本 |
| 噪音種子可重建 | ✅ 新增 `mix_at_snr_logged`,位元完全重建 |

**技術上這是本專案品質最高的一段程式。問題純粹在效度:**

- SNR 是**可聽度 / 作業難度**的維度,不是**子音身分**的維度。
  沿 SNR 軸移動,受試者不是「越來越覺得像 p」,而是「越來越聽不清楚」。
- 我們宣稱要研究的是**子音的語音表徵與顏色的關聯**。
  SNR 軸量到的是「在噪音中還聽不聽得到」,那是**另一個問題**。
- ⚠️ 附帶風險:改變 SNR 可能同時改變**響度**知覺 —— 一個沒被宣告的第三維度。
- ⚠️ 噪音本身不是中性載體:在同型作業裡,**單是噪音的隨機樣本就解釋 8–13% 的音素反應**。
  (已用記錄種子的方式保留可追溯性,成本為零。)

### 2.7 即使拿到自然音,token 變異仍是隱藏成本

這是最後一輪查證的結果,**它讓「找到自然錄音就解決了」這個期待落空**:

- 語者內 VOT 標準差:**/pʰ/ 12–27 ms、/b/ 2–8 ms**(Chodroff & Wilson 2017)
- 聽者在 VOT 軸上的內在知覺雜訊:**≈ 10.7 ms**(Clayards et al. 2008)
- → **/p/ 的 token 變異比聽者自己的知覺雜訊還大**,而且是 /b/ 的 **3–4 倍**(不對稱)

模擬結果(我方跑的):

- token 變異**只衰減 ρ**,精確等於 ρ/√(1+s²),**不製造假相關** ——
  所以它**不會偽造出 intrusion 效果**,這是好消息。
- ⚠️ **但不對稱的 token 變異會把決策界線推移 0.07–0.18 SD,偽裝成反應偏差。**
  **這對 AVWM 特別麻煩,因為注意力提示操弄看的正是界線位移。**

## 3. 為什麼這不是「再努力一下就好」

四條路擋住的原因**性質不同**,不能靠同一種努力解決:

- §2.2 是**工具的架構限制** → 換工具(KlattGrid),但代價見 §2.5
- §2.4 是**素材不存在** → 只能寫信要,或自己錄
- §2.6 是**效度問題** → 再多工程都修不好,因為量錯東西
- §2.7 是**統計性質** → 自然音本身帶進來的,不是實作瑕疵

**唯一同時繞過全部四項的方向是自己錄音**,但那要語音室、母語語者、
與一套錄音規範(`90_Sources/recording-protocol.md` 已備),是另一個量級的投入。

| | F 解決 | F 不解決 |

| 成本、自然度、母音、授權 | ✅ 全部 | |
| 刺激取樣(Clark/Westfall) | | ⛔ **仍是 q=1**:一位語者、一對端點。9 步是同一條連續體上的點,不是 9 個獨立樣本 |

   剩餘的檢查點:staircase 大多採樣邊界附近,**端點本身的採樣少** ——
   若仍想確認端點飽和,pilot 加 10 次/端點即可。
2. **適應階段的目標正確率**(`OVERALL_ACC = 0.64`,GRTv2.py 的官方 AGRT 階段)。
   ⚠️ 數字更正:0.64 經 `estimateGRTintensities` 的雙重開根號後 =
   **聯合 80%、每維 89.4%**(不是先前說的每維 80%)。兩維對稱。
   要調整就改這一個常數:0.81 → 聯合 90%、每維 94.9%。
3. **⛔ 指導語與計分的張力**(opus 核實,詳見 [[voicing×顏色互動_資料怎麼量到]] §3.1):
   指導語寫 "report which item was there"(報告被指位置原本的項目),
   但 probe 在 cue 位置呈現的是 **target 的內容**,計分的 correct = 選 target。
   **照指導語做的人在 invalid 試次會一律被記成 intrusion。**
   relation 之間的**相對**不對稱仍可解讀,intrusion 的**絕對水準**不可。
   指導語要改成什麼(報告 probe?回憶原位置?)是設計決定,要討論。
4. **q=1 範圍聲明**:怎麼寫由作者定,素材已備([[q1範圍聲明_素材]])。
5. **試次數**(96/刺激 vs Silbert 200):等 pilot 效果量出來再算 power 定案。
6. **voicing×顏色一致性對比的定位**(查證見 [[voicing與顏色的跨感官對應]]):
   文獻預測在等明度只動色相的設計下這個對比**趨近零** —— 聲音↔顏色對應幾乎
   全掛在明度通道,而明度被我們固定住了。兩種讀法擇一:
   (a) 當**控制**:一致性為零是設計的乾淨性證據,intrusion 比較不被配對偏袒污染;
   (b) 當**賣點**:若要主張 voicing×顏色一致性,設計得讓明度可變 —— 與現行單屬性
   軸的決定衝突,需要取捨。另注意:若在現設計下**仍**測到一致性,知覺路徑已被關閉,
   效應只能走語意路徑(voiced↔邪惡/負面),那會是可發表的新發現而非污染。

## 回查線索
**為什麼不用 VOT?** → 不是不想,是 MBROLA 渲染不出來(/b/ 釘在 −6.5…−2.5 ms 且非單調),
而且手上沒有自然錄音可以 splice。
**`be.wav` 是自然音嗎?** → **不是。** 與 espeak 輸出逐取樣點完全相同。
**SNR 哪裡不好?** → 技術上很好(誤差 1e-15 dB)。它量的是可聽度,不是子音身分。
**找到自然錄音就解決了嗎?** → **不會。** /p/ 的 token 變異(12–27 ms)比聽者的知覺雜訊
(≈10.7 ms)還大,而且不對稱,會把決策界線推移 0.07–0.18 SD 偽裝成反應偏差。
